# Проверка пользовательского процесса — 17.11.2026

Это мысленный прогон ТЗ и текущих документов, а не проверка работающего веб-приложения. Веб-интерфейс пока не реализован, локальная база не стала рабочим реестром. Уточнения внесены в [раздел 16 веб-ТЗ](ТЗ-ЛОКАЛЬНЫЙ-ВЕБ.md).

| Сценарий | Ожидаемый путь | Что проверять / что пока не готово |
| --- | --- | --- |
| Сообщения из одного чата | Назвать чат один раз, вставить пакет и наценку на обозначенные позиции; сохранить исходник, разобрать варианты, показать результат. | «+1%» означает +1 процентный пункт (10% → 11%), если пользователь указал наценку для этой группы. Прототип не ведёт наценки и не является веб-реестром. |
| Несколько источников | Сохранять каждый пакет со своим чатом; одинаковые ИНН проверять с учётом получателя. | Если граница источников не ясна, не угадывать. Полнота истории не подтверждена. |
| Карточка и условия | Скопировать доступный файл в хранилище, связать с компанией и источником, показывать статус и возможность скачать. | Неизвестная связь/повреждённый файл — проверка; пользователь может подтвердить связь словами, что не является внешней проверкой. Отсутствие карточки не блокирует пригодный текст без отдельного требования. |
| Новые данные днём | После записи и обновления страницы показать новые или требующие проверки задачи у назначенных получателей. | Нет автоматического чтения мессенджеров; источники и получатели пользователь указывает отдельно. Если приложение недоступно, нельзя обещать обновление кабинета. |
| Совпадение между чатами | Своя компания по известному ИНН исключается; одинаковые предложения разных источников не дублируются в одном блоке; более низкая исходная ставка сопоставимых вариантов показывается первой, различия существенных условий — на проверку. | Неполная история или неясный ИНН требуют проверки; система не видит то, что ей не передали. |
| Наценка | Для каждого указанного варианта внутри кабинета показать исходную ставку, наценку и итог; в копии — итог. | Не указанное правило не приравнивается к нулю. «+1%» — это +1 процентный пункт; округление ещё требует согласования. |
| Поиск под запрос | По названию, ИНН или назначению показать известные варианты, источник, дату и документы. | Старые предложения не выдавать за актуальные; неизвестные параметры — отдельно. |
| Блок и отправка | Выбрать позиции, проверить текст, скопировать, вручную отправить и отметить фактически отправленные позиции и файлы. | Копирование не отправка. Фактический текст может быть неизвестен; уже выполненный факт нельзя терять при устаревании. |
| Изменение условий или ошибки | Сохранить историю, создать новую версию, повторно проверить и не пересылать автоматически. | Два человека всё ещё могут физически отправить одно сообщение до регистрации в системе. |

Проверка на сложность: первый этап ограничен локальным вебом, одним общим тестовым входом, списком чатов, поиском, карточками, задачами и отметками. Нет автоматической рассылки, интеграции мессенджеров, назначения сотрудников или публичного сервера. История и проверки поддерживают эти действия, но не должны требовать отдельного подтверждения для каждой строки, когда пользователь уже ясно задал условия для группы.

Уточнение пользователя: у каждой компании всегда показывается отдельная строка НДС, не зависящая от ценовых вариантов. При отсутствии данных — «НДС: не указан», до уточнения значение не выдумывается. Это требование пока описано в ТЗ и не реализовано в прототипе.
