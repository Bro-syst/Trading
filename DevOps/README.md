# DevOps: серверный запуск

Здесь собираются инструкции и проверенные особенности развёртывания, обновления и обслуживания проекта на серверах. Добавляя сведения, указывайте дату, окружение и результат проверки; планы и предположения обозначайте отдельно от выполненных действий. Не записывайте сюда пароли, токены, закрытые ключи и другие секреты.

## Текущее состояние

На 17.11.2026 серверное развёртывание и удалённый доступ агента не настроены. Веб-кабинет предназначен для локального испытания и слушает `127.0.0.1`; готовой инструкции для публичного запуска пока нет. Рабочий учёт ведётся в Markdown, а тестовая SQLite-база не заменяет его.

## Что зафиксировать при подготовке сервера

- Сервер и окружение: назначение, версия ОС и Python, расположение программы и данных, порядок доступа и проверка идентичности экземпляра.
- Запуск и обслуживание: установка зависимостей, настройка службы, проверка работоспособности, журналы, обновление и откат — после их реализации и проверки.
- Безопасный доступ пользователей и агента, права и способ хранения секретов без самих секретов в репозитории. Локальный прототип не следует публиковать напрямую как готовый публичный сервис.
- Резервирование и проверенное восстановление базы вместе с документами; при активном SQLite WAL использовать штатный backup или согласованный снимок, а не копирование только файла базы.
- Перенос и сверку данных, испытания и порядок приёмки до возможного перехода с ручного учёта.

## Ссылки на документы: подготовка серверной конфигурации

Получателю доступен только явно выбранный файл по отдельной непредсказуемой ссылке. Ссылка является ключом доступа: каждый, кому её переслали, может скачать файл. Срок действия автоматически не ограничивается; снятие отметки отзывает соответствующую ссылку. Не публикуйте ссылку, если документ не предназначен для передачи. Отправка и скачивание ссылки не записываются как факт передачи предложения.

План конфигурации: в окружении процесса кабинета задать `PUBLIC_BASE_URL=https://files.example.com`, заменив адрес на настоящий HTTPS-домен. Это базовый адрес без пути, учётных данных, параметров или завершающего пути. Выдавать извне только `/public/documents/`, проксируя этот путь через Nginx на локальный процесс приложения. Не настраивать `alias` на папку исходников, базы или весь экземпляр, не включать листинг каталогов; приложение проверяет токен и целостность файла. Пример для отдельного HTTPS-хоста после настройки сертификата; первая строка размещается в контексте `http`, за пределами `server`:

```nginx
limit_req_zone $binary_remote_addr zone=files_limit:10m rate=10r/m;

server {
    listen 443 ssl;
    server_name files.example.com;
    ssl_certificate     /etc/letsencrypt/live/files.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/files.example.com/privkey.pem;

    location ^~ /public/documents/ {
        access_log off;
        limit_req zone=files_limit burst=10 nodelay;
        proxy_pass http://127.0.0.1:8765;
        proxy_set_header Host 127.0.0.1:8765;
        proxy_hide_header Set-Cookie;
    }
    location / { return 404; }
}
```

Это образец, а не проверенное развёртывание: сервер, домен, TLS, Nginx и доступ из интернета ещё не настроены. Перед использованием необходимо проверить извне скачивание выбранного файла без авторизации, отказ для произвольного токена и после снятия отметки, а также недоступность кабинета, базы и других файлов на этом хосте. Значение `PUBLIC_BASE_URL` проверяется только синтаксически: оно само по себе не подтверждает владение доменом, сертификат, DNS или доступность ссылки.

Адрес ссылки содержит секрет. `access_log off` в примере отключает только журнал доступа: URI может попасть в журнал ошибок Nginx, журналы других прокси или мониторинга. До публикации проверьте всю цепочку, ограничьте доступ к журналам и исключите запись токенов либо настройте их редактирование. Считать резервные копии базы содержащими секреты и защищать их соответствующим образом.

Восстановление старой копии базы может снова включить ссылки, отозванные после создания копии. До подключения восстановленного экземпляра к внешнему адресу сверяйте историю отзывов с более поздними данными. Если надёжной сверки нет, не включайте внешнюю выдачу до отзыва всех прежних ссылок и проверки результата: функции массового отзыва пока нет. Отзыв не удаляет файлы, уже скачанные получателями. При смене домена старые отправленные адреса остаются доступными, пока их старый маршрут работает: при необходимости отключите его отдельно.

В текущем прототипе публичные запросы обрабатываются тем же процессом, что и кабинет, файл целиком считывается в память, а поиск ссылки зависит от размера истории. Ограничение частоты по IP в примере не защищает от всех видов нагрузки. Перед реальным запуском проверьте размеры файлов, параллельные скачивания, медленных клиентов и работу при росте числа ссылок; по результатам настройте ограничения Nginx и при необходимости доработайте сервер. Публичная устойчивость текущего решения не подтверждена.

Публичный хост файлов не решает задачу безопасного размещения самого кабинета: его локальные проверки адреса, сессии и происхождения запроса и текущая тестовая конфигурация не предназначены для прямого открытия в интернет. Доступ к кабинету и переход на сервер требуют отдельной настройки и приёмки.
