# Локальный кабинет: пробный запуск

Это испытание на одном компьютере. Сервер слушает только `127.0.0.1`; публикация в интернете и переход рабочего учёта на базу не выполнены. База, показанная в пробном кабинете, содержит вымышленные данные. Рабочие Markdown-файлы и исходные документы остаются основным реестром до отдельного завершения перехода и сверки.

## Запуск нового примера

Чтобы открыть существующую проверенную **тестовую** копию с ранее введёнными чатами и поддержкой счетов, находясь в папке проекта, выполните:

```sh
python3 web.py --root '.local-data/общий-тест-v3' --port 8765
```

В этом экземпляре сохранён прежний тестовый пароль. Чаты — из списка пользователя; кроме вымышленных предложений, для проверки внесены пример счёта S01 от ZLAT-2 / РР, предложение S02 от «Феликс / НН / РР», предложения M01–M14 и счета S03–S08 от «МОС.ДОМ НОВАЯ / РР»; они находятся на проверке. Копия не является рабочим реестром. Проверенная миграция из прежнего тестового экземпляра выполнена 18.11.2026 с сохранением исходного экземпляра; новые данные между экземплярами и рабочим журналом автоматически не синхронизируются. Каталог исключён из Git, поэтому его необходимо учитывать при отдельном резервировании.

Чтобы создать **новый отдельный** пример:

В терминале, находясь в папке проекта, выполните:

```sh
python3 web_fixture.py /private/tmp/trading-web-demo
python3 web.py --root /private/tmp/trading-web-demo --setup-password
python3 web.py --root /private/tmp/trading-web-demo --port 8765
```

Для новой папки примера выберите путь, которого ещё нет. При настройке пароль вводится дважды и не отображается. Для локального сброса запустите ту же команду `--setup-password` для нужного экземпляра и задайте новый пароль; прежний пароль не раскрывается. Затем откройте в браузере `http://127.0.0.1:8765/`. Остановить сервер можно сочетанием Ctrl+C в его терминале. Временная папка может быть удалена системой; не используйте её для рабочих данных. Если порт занят, выберите другой с помощью `--port` и откройте соответствующий адрес.

## Общий текст без адресата

В разделе «Предложения по источникам» выберите отдельные или все видимые позиции и нажмите «Общий текст». Просмотр показывает только текст предложений; его можно отредактировать и сразу скопировать. Временные изменения в общем окне не сохраняются в карточки. Конкретный получатель не задан, поэтому проверка его входящих предложений и истории отправок не выполняется. Копирование не фиксирует отправку. Существующий путь подготовки для конкретного получателя действует отдельно.

## ИНН на локальном этапе

Корректный по контрольной сумме ИНН без зафиксированной внешней проверки сам по себе не блокирует предложение. Такой ИНН используется для поиска совпадений и запрета возврата собственных предложений; это не подтверждение идентичности компании. Реальные конфликты ИНН, неопределённые условия и вопросы счетов остаются на проверке. Пилотная база не содержит всю историю чатов и не заменяет ручную сверку.

## Ручные товарные группы и светофор

В разделе «Предложения по источникам» раскройте карточку, выберите цвет в списке светофора и нажмите общую кнопку «OK». Товарные группы сразу доступны в раскрытой карточке и сохраняются той же кнопкой. Цвет и группы относятся к конкретному варианту и дате предложения; решение сохраняется в истории тестовой базы. Если в актуальном сохранённом тексте есть одна понятная строка «Светофор», при изменении только цвета она обновляется автоматически. При неоднозначном или уже устаревшем тексте нужна ручная сверка. В «Дополнительных фильтрах» можно искать по группе; список групп задаётся файлом [ТОВАРНЫЕ-ГРУППЫ.md](ТОВАРНЫЕ-ГРУППЫ.md). Решения из тестовой базы автоматически не переносятся в рабочий Markdown-реестр.

Документы предложения отображаются на карточке. Зарегистрированный целый файл можно скачать, даже если он ещё не проверен: ссылка помечена «Скачать для проверки». Скачивание не подтверждает файл или отправку. Отсутствующий, изменённый или неправильно связанный файл не выдаётся.

## Как испытать

После входа открывается список активных предложений за сегодняшнюю локальную дату. В «Чат-источник» доступны только чаты, приславшие активные варианты на выбранную дату; число рядом с чатом — число вариантов. Дату можно сменить, а предложения отфильтровать по типу или найти по названию и ИНН. В списке источника отметьте отдельные варианты или нажмите «Выбрать все видимые», затем «Выбрать получателя» и «Проверить выбранные». Кабинет сверит выбор с очередью указанного чата, покажет результат по каждой позиции и автоматически отметит для предпросмотра только доступные. Нажмите «Предпросмотр», чтобы получить текст и скопировать его; позиции на проверке, исключённые и уже отправленные в текст не попадают. Также можно открыть «Чаты-получатели» и выбрать позиции непосредственно в очереди: готовность и пересечения оцениваются отдельно для каждого чата. Карточки показывают условия, НДС, исходную цену и согласованную наценку. Откройте источники, сформируйте блок и скопируйте его; отдельно укажите фактически отправленные позиции и документы. В истории можно посмотреть и исправить отметку. Поиск позволяет найти компанию и источник. Список получателей настраивается в кабинете; запись входящих сообщений и обработку документов выполняет ассистент через CLI.

Подготовка блока и его копирование сами по себе не означают отправку. Не отмечайте как отправленные данные, которые фактически не переданы. В тестовом примере никакой автоматической отправки в чаты нет.

## Для ассистента и разработчика

Сначала прочитайте [README](README.md), согласованное [ТЗ локального веба](ТЗ-ЛОКАЛЬНЫЙ-ВЕБ.md) и [контракт CLI](КОНТРАКТ-CLI.md). У веба и CLI должен быть один и тот же `--root` экземпляра и его база `registry.sqlite`; данные из разных экземпляров автоматически не объединяются. Пользователь присылает сообщения, дату, название чата-источника, документы и согласованную наценку обычным языком. Ассистент сохраняет первичный текст, делает структурированный разбор, прикрепляет документы и фиксирует подтверждённые решения командами CLI. Программа не разбирает произвольные сообщения автоматически.

Для переноса базы v1 в схему v2 предусмотрена команда `python3 web.py --root НОВАЯ_ПАПКА --migrate-copy ПАПКА_V1`: она работает с копией и не заменяет исходный экземпляр. Такой перенос сам по себе не является переводом рабочего учёта: необходимы сверка, резервные копии и испытания согласно ТЗ. Не подменяйте действующий реестр тестовой базой.

Для теста счетов нужна схема v3: `python3 web.py --root НОВАЯ_ПАПКА_V3 --migrate-copy ПАПКА_V2`. Создаётся отдельная копия v2 с зарегистрированными файлами; оригинал не заменяется. Старые подготовленные блоки после обновления могут отображаться как устаревшие: их сохранённые тексты и факты отправки остаются в истории, а неотправленный блок можно подготовить заново после проверки. Демонстрационный `web_fixture.py` по-прежнему создаёт v2, поэтому для испытания счетов сначала создайте этот пример, затем перенесите его в новый каталог v3 и задайте пароль для нового экземпляра. Исторический пилот v1 сначала переносится в v2, затем отдельно в v3. Инструкции для обработки счетов — в [контракте CLI](КОНТРАКТ-CLI.md) и [ТЗ счётов](ТЗ-ОПЛАТА-СЧЕТА.md).

### Клиентские тексты

В источнике откройте «Текст для клиента» у предложения: заготовку можно проверить, исправить и сохранить для повторного использования. Выделите нужные предложения и выберите общий текст без получателя. Проверки и внутренние замечания остаются в кабинете, не в копируемом блоке. Неоднозначные свободные условия и полное назначение платежа проверяются по исходнику и при необходимости вручную переносятся в текст. При изменении исходных данных сохранённый текст помечается устаревшим и требует повторного сохранения. Общий текст не проверяет пересечение с получателем и не фиксирует отправку; для конкретного чата используйте очередь получателя. База остаётся тестовой и автоматически с Markdown не синхронизируется.

### Загрузка файлов к предложениям

В «Предложениях по источникам» нажмите на название файла, чтобы скачать его, или на ⓘ рядом, чтобы увидеть сведения. Для загрузки откройте «Добавить файлы», выберите до десяти файлов и нажмите «Загрузить». Один файл — до 10 МиБ, весь пакет — до 20 МиБ. Файлы сохраняются копиями в каталоге экземпляра, а их связь и история — в его SQLite; ранее загруженные копии не заменяются. На карточке счёта добавляемые файлы связываются с этим счётом, на карточке компании — с компанией. Файлы остаются непроверенными; загрузка не подтверждает их происхождение, условия или отправку. При добавлении файлов актуальный сохранённый текст переносится без изменений, если остальные данные предложения не изменились; ранее устаревший текст по-прежнему требует сверки. Рабочий Markdown и тестовая база не синхронизируются автоматически; для переноса нужны база и файлы.

### Условия НДС предложения

На карточке в источниках выберите значение в поле «Условия НДС предложения» и сохраните. Те же значения доступны в дополнительных фильтрах; позиции с неопределённым условием показываются отдельно. Условие относится к варианту предложения, а НДС компании и счёта учитываются отдельно. Оригинальные условия не перезаписываются. Если клиентский текст нельзя однозначно обновить, его нужно сверить вручную.

### Проверка и комментарий на карточке

В источниках и в очереди получателя карточка позволяет поставить или снять «Проверено», редактировать клиентский комментарий и использовать общие поля и файлы. Отметка записывает решение пользователя для текущих данных; при их изменении требуется новая проверка. Совпадения с получателем, предыдущая передача и отсутствие согласованной цены обрабатываются отдельно. Комментарий добавляется отдельной строкой в текст клиенту; пустой комментарий не добавляется. Изменение комментария не переписывает исходное сообщение или ранее сохранённый текст и делает ранее подготовленный блок устаревшим. Отметка не подтверждает документ или отправку.

### Назначение, цена и выдача

В списке краткая карточка показывает источник с мессенджером, светофор и сохранённый текст для клиента. Сохранённый комментарий виден в краткой карточке; нажмите на неё, чтобы открыть поле комментария, остальные поля и файлы. Измените нужные поля и нажмите общую кнопку «OK», которая активна при несохранённых изменениях. Назначение, цена, выдача, НДС, светофор, группы, комментарий и отметка «Проверено» сохраняются одной операцией; загрузка и выбор файлов остаются отдельными действиями. Статус показывает несохранённые изменения и конфликты. При закрытии страницы с черновиком браузер предложит подтвердить уход. Цена относится к передаче клиенту; исходная ставка поставщика и прежняя наценка сохраняются в истории. Срок можно выбрать только из четырёх вариантов: «День в день», «Следующий день», «Через день», «3 - 4 дня». Старое значение сохраняется, пока новый срок явно не выбран. Изменения относятся к конкретному предложению, сохраняются с происхождением пользователя и влияют на актуальность проверки и подготовленных блоков. Если в ранее сохранённом тексте есть ручные правки, проверьте его после изменения полей; исходные сообщения и исторические блоки не переписываются. Отредактированные поля поддерживаются веб-кабинетом; подготовка через CLI для таких вариантов остаётся на проверке.

В раскрытой карточке также доступны поля БИК и Р/С. БИК вводится девятью цифрами, расчётный счёт — двадцатью; каждое поле можно оставить пустым. Введённые значения относятся к конкретному варианту предложения, сохраняют ведущие нули и видны в краткой карточке как внутренние сведения. Для счетов с префиксами 405–408 дополнительно рассчитывается контрольный ключ по алгоритму для счёта кредитной организации; счета других типов этим алгоритмом не проверяются. Для счёта в Банке России используется другой порядок, поэтому результат по алгоритму кредитной организации не является окончательным. Несовпадение ключа не препятствует сохранению и последующему исправлению. Проверка не подтверждает существование счёта или его принадлежность. Система не переносит реквизиты между предложениями и автоматически не добавляет их в текст для передачи. Существующие данные не заполняются из файлов или сообщений автоматически; изменение только этих внутренних реквизитов и товарных групп не делает актуальный текст устаревшим. Ранее устаревший или неоднозначный ручной текст по-прежнему требует проверки.
